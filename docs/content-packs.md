# Content packs

A content pack is a repository that holds the questions and exam configuration for
one exam. The app ships no official questions of its own. It bundles a small demo
pack for development and the accessibility gate, and installs every real exam from
the pinned manifest in `content/packs.json`.

The upstream repository starts with an empty manifest (`{}`), so a fresh fork
renders the demo exam only. Every pack is installed explicitly with
`pnpm content:add`, which copies the files and records the pin.

This page covers the manifest, the pack layout, what a sync is allowed to write,
and the schema-version contract. For the question rules themselves see
[authoring](./authoring.md), for installing packs in your own deployment see [make it your own](./fork-your-own.md).

## How the app finds a pack

`content/packs.json` maps an exam slug to a pinned source. An installed pack looks
like this:

```json
{
	"cpacc": {
		"source": "https://github.com/mocks-org/mocks-cpacc",
		"ref": "bde1b60cf1ba5f04c5cfb51f0b6e2d2d24870f24"
	}
}
```

- The key is both the directory name (`content/cpacc/`) and the exam slug declared
  by `exam.json`. They must agree.
- `source` is a portable locator. The sync CLI accepts
  `https://github.com/owner/repo`, `git@github.com:owner/repo`,
  `github:owner/repo`, `owner/repo`, or a local path, and writes the normalised
  remote form (or the value passed with `--source`) to the manifest. Commit a
  remote URL, not a local path, or the pin stops working on another machine.
- `ref` is a **full 40-character commit SHA**, never a branch or tag. A tag can be
  moved and a branch changes under you, a SHA makes the build reproducible and
  the diff auditable.

The bundled `content/demo/` pack is not in the manifest and is never synced. Its
exam slug is `cpacc-demo`, and the demo directory keeps that name for continuity.
`pnpm content:check` fails if the demo is pinned or if a manifest entry and a
`content/` directory disagree.

The content directory is build-time input. The running app reads questions from
D1, so installing a pack is followed by `pnpm bank:seed:local` (or `:remote`).
Removing a pack has the same split: `pnpm content:remove <exam>` deletes the files
and the pin, but the rows stay in D1 until you reseed that database. Deleting a
local `.wrangler/state/v3/d1` and re-running `pnpm db:migrate:local` plus
`pnpm db:seed:demo:local` gives a clean local slate.

## Pack layout

The root of a pack repository is shaped exactly like one exam directory inside
`content/`:

```
mocks-cpacc/                    # pack root == content/cpacc/
├── exam.json                   # exam row: title, provider, duration, counts, status
├── exam/
│   ├── bank.json  # bank settings, schemaVersion, module draw counts
│   └── questions/
│       └── <module>/<question-id>.json
├── practice/    # optional second bank kind (for untimed practice)
│   ├── bank.json
│   └── questions/<module>/*.json
├── README.md
├── LICENSE
└── CONTRIBUTING.md
```

- Every directory directly under the pack root that contains a `bank.json` is a
  bank kind. `exam` and `practice` are the kinds the app knows how to draw from.
- `exam.json` is the per-exam configuration. It is not hardcoded anywhere in the
  app. `bank.json` carries the bank settings and its module list. Exam
  modules carry a draw count, practice modules leave it empty.
- Each question is one JSON file named by its ID, under
  `questions/<module>/`. The full-bank JSON and SQL are generated by the
  app and are never committed to a pack.
- `README.md`, `LICENSE`, and `CONTRIBUTING.md` travel with the pack so the synced
  directory remains self-describing. The app does not render them.

A minimal `exam.json`:

```json
{
	"id": "cpacc",
	"slug": "cpacc",
	"title": "CPACC",
	"provider": "IAAP",
	"providerUrl": "https://www.accessibilityassociation.org/cpacc",
	"unofficial": true,
	"contentLocale": "en",
	"blueprintVersion": "v0.0.1",
	"durationMinutes": 120,
	"questionCount": 100,
	"optionCount": 4,
	"passPercent": 80,
	"sampling": "stratified",
	"questionOrder": "mixed",
	"optionOrder": "shuffle",
	"optionLabelStyle": "numeric",
	"disclaimer": "The official CPACC exam is administered by IAAP, which sets the curriculum, fees, booking, scoring and proctoring.",
	"status": "published"
}
```

A matching `exam/bank.json`:

```json
{
	"schemaVersion": 3,
	"exam": "cpacc",
	"bank": {
		"id": "cpacc-exam",
		"kind": "exam",
		"title": "Mocks CPACC Exam Bank",
		"version": "0.1.0",
		"status": "published",
		"optionCount": 4
	},
	"modules": [
		{
			"id": "disabilities",
			"title": "Disabilities, Challenges, and Assistive Technologies",
			"questionCount": 40
		},
		{
			"id": "accessibility",
			"title": "Accessibility and Universal Design",
			"questionCount": 40
		},
		{
			"id": "standards",
			"title": "Standards, Laws, and Management Strategies",
			"questionCount": 20
		}
	]
}
```

## What a sync may change

A sync is deliberately narrower than a fork merge. It validates the pack in a
temporary clone and only then replaces `content/<exam>/` and updates the pin. It
never touches `src/`, `package.json`, migrations, workflows, or configuration.

The allowlist is enforced before anything is copied:

```
exam.json
<kind>/bank.json
<kind>/questions/**/*.json
README.md
LICENSE
CONTRIBUTING.md
```

Repository metadata (`.git`, `.github`, `.gitignore`, `.gitattributes`) is skipped.
A pack that contains anything else is refused with the offending path. Question
files must end in `.json`, empty files are treated as placeholders rather than
questions.

The same boundary is enforced in CI. **Actions → Sync content** runs the sync,
validates every pack, and fails if `git diff` shows a path outside `content/`
before it opens a pull request. Upstream content therefore arrives as a reviewed
PR, never as a direct push, so a bad sync can be closed without data loss.

## The schema-version contract

`schemaVersion` appears in every `bank.json` and versions the authoring contract,
not the question set. The app supports **version N and N-1**; with the current
app that is `3` and `2` (`SUPPORTED_SCHEMA_VERSIONS` in
`src/lib/authoring/schema.ts`).

- `pnpm content:check` reads `bank.json` without loading questions and fails when a
  pinned pack declares an unsupported version. The message names the versions the
  app accepts.
- `pnpm content:add` and `pnpm content:update` run the full validator and refuse an
  incompatible pack before writing anything.
- To adopt a new schema version, update the pack and bump `bank.version`, tag a new
  release, then move the pin with `pnpm content:update <exam>`. The app widens the
  supported list only after a migration exists.

Other rules are checked by the same validator whenever a pack is loaded:

- `bank.json.exam` must equal `exam.json.slug`, and `bank.optionCount` must equal
  `exam.optionCount`.
- Exam module draw counts must add up to `exam.questionCount`. A published bank may
  contain only published questions, and a published bank requires a published exam.
- Question IDs are unique across **every** loaded pack, not just within a bank.
- A bank must not contain the same question twice (stem, options, and correct
  answer), even under different IDs.
- Every question needs at least one reference; published questions need
  `reviewer`, `reviewedAt`, and `sourceCheckedAt`; `TODO` placeholders and images
  are rejected.

The full field-level rules are in [authoring](./authoring.md).

## Write your own pack

1. **Create a repository** with the layout above and a licence of your choice. The
   pack is content only, it must not contain app code.
2. **Write `exam.json`.** Pick a unique slug. It becomes the manifest key, the
   `content/<exam>/` directory name, the question ID prefix, and the public route
   (`/portal/<exam>`).
3. **Write one `bank.json` per bank kind.** Start with an `exam` bank. Module IDs
   are referenced by every question, so settle them first. A practice bank is
   optional, it uses `"kind": "practice"` and `null` draw counts.
4. **Write questions** as one file per question. See [authoring](./authoring.md)
   for the shape, the ID convention, and the review metadata.
5. **Validate against the app.** From the pack root:

   ```sh
   node ../mocks/scripts/bank/validate.ts .
   node ../mocks/scripts/bank/length-audit.ts .
   node ../mocks/scripts/bank/link-check.ts .   # network
   ```

   The first command exits non-zero on errors, `--strict` makes the length audit
   fail on its findings as well. A pack repository can run the same commands in CI
   against a pinned app commit, see the CPACC pack's
   [workflow](https://github.com/mocks-org/mocks-cpacc/blob/main/.github/workflows/validate.yml)
   for a working example. A private app repository needs an explicit
   `MOCKS_APP_REPOSITORY` variable and a read-only `MOCKS_APP_TOKEN` secret, since
   another repository's `GITHUB_TOKEN` cannot read it. `MOCKS_APP_REF` (a full
   commit SHA) pins the app checkout; the example workflow carries a fallback SHA,
   so move both together when you re-pin the app. The SHA must exist in the
   repository named by `MOCKS_APP_REPOSITORY`: a fork shares history with upstream,
   but a repository created from an older template copy does not, so upstream app
   SHAs will not resolve there.

6. **Tag a release** (`v0.2.0`, …) and push the tag. The tag is a human label; the
   app pins the SHA it points at.
7. **Install it in the app**:

   ```sh
   pnpm content:add github:<owner>/<pack> --ref <sha>
   pnpm bank:validate
   pnpm bank:seed:local
   ```

   `--ref <sha>` installs an exact release; without it, `content:add` takes the
   newest tag and records the commit it points at. Either way the manifest ends up
   with a full SHA, so the install is reproducible.

   Commit `content/packs.json` and `content/<exam>/**` together. If a sync from a
   local checkout has to predate the remote push, pass
   `--source github:<owner>/<pack>` so the committed source stays portable.

## Install, update, remove

| Command                                    | Behaviour                                                               |
| ------------------------------------------ | ----------------------------------------------------------------------- |
| `pnpm content:add <source> [--ref <sha>]`  | Fetch, validate, install to `content/<exam>/`, write the pin            |
| `pnpm content:update [exam] [--ref <sha>]` | Re-fetch and replace; default is the newest tag, falling back to `HEAD` |
| `pnpm content:remove <exam>`               | Delete the directory and its manifest entry                             |
| `pnpm content:list`                        | Exam, short ref, bank versions, question counts                         |
| `pnpm content:check`                       | Manifest, directories, exam slugs, and schema versions agree            |

All of `add`, `update`, and `remove` accept `--dry-run`, which prints what would
change and exits without writing. `content:add` refuses an installed pack unless
you pass `--force`; prefer `content:update`.

A sync that writes anything outside `content/` is a bug. Treat a diff in `src/` or
a config as a failed sync, not as something to keep.

## Licensing

- App code is MIT. A pack's content is licensed by that pack, CPACC uses CC BY-SA
  4.0.
- The licence file is synced with the pack, but the footer links come from
  `site.licenseLinks` in `src/lib/settings/site.ts`. Update them when you change
  packs.
- **Share-alike:** if you distribute a modified copy of CC BY-SA content, your
  version must stay under CC BY-SA 4.0 with attribution. Your own pack may use any
  licence you like.
- Every deployment must state that it is unofficial and that scores are practice
  feedback, not official results. The copy lives in `site.ts`.

## Troubleshooting

| Message                                                             | Fix                                                                                                   |
| ------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| `pins "x", but content/x/ does not exist`                           | Run `pnpm content:add … --ref <sha>` (new), `pnpm content:update x` (installed), or remove the entry. |
| `content/x/ is not pinned in content/packs.json`                    | Add it with `pnpm content:add`, or delete the directory.                                              |
| A pack is still listed in `pnpm dev` after removing it              | D1 still holds its rows. Reseed the database, or delete `.wrangler/state/v3/d1` and re-migrate.       |
| A freshly added pack does not appear in the app                     | `content:add` copies files but does not seed. Run `pnpm bank:seed:local --exam <slug>`.               |
| `The directory name and manifest key must match the exam slug`      | Rename the directory or change `exam.json`/the manifest key.                                          |
| `uses schemaVersion N, but this app supports …`                     | Use a supported schema version, or update the app.                                                    |
| `Question ID … is already used by …`                                | Two packs share an ID prefix. Make the slugs and prefixes unique.                                     |
| `Pack contains …, which is outside the allowlist`                   | Move app code, fixtures, or notes out of the pack repository root.                                    |
| `The sync wrote outside content/. Refusing to open a pull request.` | A sync bug or a non-pack repository. Do not merge the PR.                                             |
